| -- | ---: | ---: | ----: |

北京、成都超过一半的单品**不是所有店都卖**。「你想吃的那款，附近这家没有、隔两条街的有」——这是比「贵几块钱」更高频的真实信息差。

### 3. 门店券：同城高度一致，**券维度没有套利空间**（对 V2 设计的诚实修正）

- 到店场景：6 城中 **5 城所有门店券集合完全相同**（均为「中薯条买一送一」+「王牌小食拼」）；唯一例外是成都快捷小站少一张券
- 外送场景（梧州 2 店）：门店券同样一致
- 结论：`query-store-coupons` 的**门店级券基本无差异**；V2 文档中「券是跨店差价真正来源」的假设**不成立**，已修正

### 4. 外送场景（n=2，样本小）

- 两店配送费均为 6 元（`calculate-price` deliveryPrice=600），无差异
- 外送菜单有 2 个套餐价差 1 元（牛气满满套餐 41.5 vs 42.5）
- 样本不足以外推，仅记录

## 三、对叙事与方向的修正

**「隔一条街贵 8 块」——不成立为普遍现象。** 8 元来自特殊店型（快捷小站）定价策略；常规店间典型价差是 **0.5–1 元/单品，一餐 1–3 元**。且黄冈（三线）价差罕见（3.8%，最大 0.5 元）。

**但「很多门店价格不一样」——成立。** 一线/新一线城市 22%–46% 的共同单品存在跨店价差，频率不低；叠加 36%–76% 的单品覆盖率，**「同城 N 店扫一遍」的信息差是真实的**。

**修正后的方向定位**（替代 V2 原「套利雷达」表述；2026-10-13 定名「**麦探长**」）：

- 主叙事从「套利省钱」→ **「麦探长：跑遍全城的麦当劳物价侦探」**：双维度输出——① 价差榜（今日各店同餐总价排行 + 差价归因）；② 可得性提醒（你想吃的只有 X 店有）
- 传播钩子从「贵 8 块」→ 两个都真实的版本：「同城同餐差 3 块」（北京精选单人餐实测）+ 「跑了 3 家店才吃到」（可得性叙事）
- **诚实设计升级为卖点**：扫不到价差就明说「今日各店同价」；识别特殊店型（快捷小站等）并单独标注，解释极端价差来源——这正是麦搭子「不装」与其它省钱项目的分水岭
- README 演示素材直接用本次实测数据（30 店、6 城、可复现脚本），比编造的 demo 有说服力

## 四、决策建议

**做，按修正后的定位做。** 理由：

1. 价差频率（22%–46%）和可得性差异（覆盖率低至 36%）都过了「有真实信息差」的线，且 0 直接竞争；
2. 单次扫描的期望收益要按真实幅度管理预期（一餐 1–3 元），叙事诚实反而成为差异点；
3. 用户所在地黄冈价差罕见——**首屏演示建议用北京/成都数据**（价差频率高），并如实标注「三线城市价差较少」；
4. 若后续想加大筹码，可扩展维度：外送配送费（当前 n=2 无差异，需更多城市验证）、得来速（beType=5）菜单价、团餐（beType=6）报价。

**待验证项（标 UNVERIFIED，不做推断）**：价差是否随日期/活动变动（单次快照无法回答）；外送配送费跨店差异（仅 2 店样本）；得来速/团餐场景价差（未探测）。
